## Teaching

Lessons keep V3's shape (`## ` heading = one step, 5–8 steps, 600–1000 words) and gain interactive blocks, so the reader
*does* something on most screens. Every block is a fenced code block whose body is one JSON object.

### ` ```check ` (V3, unchanged)

```json
{"prompt": "…", "options": ["…", "…", "…"], "answer": 0, "explanation": "…"}
```

Must be answered before Continue. 2–4 per lesson.

### ` ```steps ` — step-through visual

Watch an algorithm, data structure or protocol change one move at a time. The reader clicks **Next** / **Back**
through frames; Continue is not blocked.

```json
{"title": "Binary search for 7", "frames": [
  {"visual": "[1] [3] [5] [7] [9]\n ^lo     ^mid    ^hi", "caption": "Middle is 5. 7 is bigger, so drop the left half."},
  {"visual": "[1] [3] [5] [7] [9]\n             ^lo ^hi", "caption": "Only 7 and 9 are left."}
]}
```

- `title`: short, says what is being traced. `frames`: 2–8. `visual`: monospace text (ASCII diagram, table, memory
  layout, a few lines of code with a `>` marker on the current line), at most 12 lines × 56 chars so it fits a phone.
  Keep columns aligned across frames so only what changes moves. `caption`: one or two plain sentences (markdown
  inline allowed).
- Use one in **See it work** or **How it works** of every lesson where something changes over time.

### ` ```reveal ` — predict, then reveal

```json
{"prompt": "Before you look: what does this print, and why?", "answer": "It prints **3**, because …"}
```

- `prompt`: a question that makes the reader think first. `answer`: markdown (short; code allowed via inline code).
- Good for "what happens if…", "spot the bug", "which would you pick". 1–2 per lesson. Never blocks Continue.
